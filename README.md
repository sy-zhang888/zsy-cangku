# zsy-cangku · 概念学习资料库

用自己写的 Skill 学习 AI 概念，并把学习过程沉淀成一个可复用的仓库。

## 这个仓库是干什么的

我用 WorkBuddy 写了一个**概念学习资料生成 Skill**，然后用它学习了三个 AI 领域的基础概念：

- **Agent（智能体）**
- **大模型的上下文（Context Window）**
- **Skill（技能）**

产出物是三份给 8-12 岁孩子看的图文学习资料，外加一份说明三者关系的关系图。整个仓库既是作业成果，也是一个能继续增长的学习工具：以后遇到新概念，只要调用同一个 Skill 就能生成新资料。

## Skill 的存放路径

```
.workbuddy/skills/concept-learning-kit/SKILL.md
```

放在仓库根目录的 `.workbuddy/skills/` 下，属于**项目级 Skill**：谁克隆这个仓库，谁就自动获得这个技能。

### Skill 的设计要点

| 项目 | 说明 |
| --- | --- |
| 元数据 | YAML frontmatter 里写明 `name` 与 `description`，符合 Agent Skills 开放规范 |
| 通用性 | 接收**任意概念名称**作为输入，不是为这三个概念写死的一次性提示词 |
| 输入 | 概念名（必填）；年龄背景、输出路径、需对比的相近概念（可选，有默认值） |
| 生成步骤 | 定锚点 → 找类比 → 查来源 → 写内容 → 做自检 |
| 输出结构 | 固定的 9 个板块：定义 / 学习目标 / 核心问题 / 类比 / 机制 / 应用 / 辨析 / 自测 / 来源 |
| 资料来源 | 要求 ≥2 个来源且 ≥1 个官方一手来源，必须给出可访问 URL 并标注支撑了哪条结论 |
| 自检 | 10 条检查清单，包括"类比要写明在哪里不准""必须写出做不到的事" |

## 在 WorkBuddy 中怎么调用它

1. 用 WorkBuddy 打开本仓库所在的目录（即 `zsy-cangku` 这一层）
2. 项目级 Skill 会被自动识别，直接在对话里说：

```
用 concept-learning-kit 学习「向量数据库」
```

3. 也可以只描述意图，WorkBuddy 会根据 `description` 自动匹配：

```
帮我搞懂「什么是 RAG」，做成学习资料
```

4. Skill 会按 `SKILL.md` 里的流程执行：先检索来源 → 按 9 个板块生成 → 保存到 `learning-materials/<概念英文名>.html` → 逐条自检后交付

## 已生成的学习资料

| 文件 | 概念 | 一句话 |
| --- | --- | --- |
| `learning-materials/agent.html` | Agent | 给它一个目标，它会自己拆步骤、用工具、做完再检查 |
| `learning-materials/llm-context.html` | 大模型的上下文 | 一次能"看见"的文字总量，问的和答的共用这一块地方 |
| `learning-materials/skill.html` | Skill | 装在文件夹里的一本岗位手册，让通用 AI 临时变成某件事的熟手 |
| `learning-materials/concept-relationship.html`<br>`learning-materials/concept-relationship.md` | 三者关系 | Agent 在工作台上干活，不会了就去翻手册 |

每份资料都包含：**一句话定义、3 条学习目标、3 个引导问题、生活类比与配图、机制拆解与配图、1 个具体应用场景、易混淆对比表与使用边界、3 道自测题（附折叠答案）、可核查的资料来源**。

直接用浏览器打开 `learning-materials/index.html` 即可从目录页进入任意一份。

## 用了 AI 之后，我做了哪些人工核查和修改

这部分如实记录，方便对照检查。

### 核查

1. **逐个访问了全部来源链接**（共 9 个，用 HTTP 请求实测返回码）：8 个返回 200，可正常打开。剩下 1 个是 OpenAI 开发者文档，对脚本请求返回 403（该站点对非浏览器流量有防护），需要在浏览器里手动打开确认；它所支撑的那条结论——"上下文窗口包含输入、输出与推理 token"——已由另一条可访问的 Claude 官方文档交叉支撑，结论不依赖单一来源。
2. **核对了关键数字与说法**：如"Skill 元数据约 100 token""SKILL.md 正文建议 5000 token 以内""description 上限 1024 字符"等，均出自官方文档，未凭印象填写。初稿里那些容易过时的具体模型窗口数值则已删除（见下方第 2 条）。
3. **逐条执行了 Skill 自带的 10 项自检清单**，不通过的地方改写后重新检查。
4. **复核了交付清单**：对照作业要求逐条核对目录结构、Skill 元数据字段、三份资料的 9 个板块、自测题数量与答案、关系说明的两个重点项，确认无遗漏（三份资料各含 3 道自测题，均配有折叠答案）。

### 修改

1. **删掉了 AI 自作主张的内容**：AI 第一次提交时未经确认就改写了 README 并新建了一份笔记，已用 `git reset --hard` 完全撤销，仓库回到初始状态后重新按需求制作。
2. **删掉了无法核实的数字**：初稿中曾出现某些模型精确的上下文窗口数值，来源不一且容易过时，已删除，改为引用官方文档的定性表述（"不同模型差别很大，要看具体模型的文档"）。
3. **给每个类比补上了"这个比喻在哪里不准"**：初稿只有类比没有边界，容易误导。三份资料都补上了这一栏。
4. **补充了"使用边界 / 做不到的事"**：初稿偏正面，已为三个概念分别补上各自的局限与常见误会。
5. **调整了语言**：删掉"赋能""一体化""智能化处理"这类空话，把抽象描述改成具体动作（例如把"能智能地完成任务"改写成"先读文件、再查资料、发现字数超了就删两段"）。
6. **统一了版式与配色**：三份 HTML 使用同一套浅色主题与卡片结构，图全部改为内联 SVG，确保离线双击即可打开。
7. **补充了 Markdown 版关系说明**：作业要求里提到 `concept-relationship.md`，而目录结构中是 `.html`，两种格式各留了一份，内容一致、呈现方式互补。

## 版本与安全

```bash
git add .
git commit -m "说明本次改动"
git push origin main
```

- 推送使用 **GitHub 个人访问令牌（PAT）**，通过系统钥匙串保存，**不写入任何文件**
- `.gitignore` 已排除 `.env`、`*.key`、`*.pem`、`*secret*`、`*credentials*`、SSH 私钥等敏感文件
- 提交前请自检：`git status` 确认没有密钥、密码、个人隐私文件被加入暂存区
- 建议为令牌设置**过期时间**，并在推送完成后到 GitHub 的 Token 设置页删除不再使用的令牌
