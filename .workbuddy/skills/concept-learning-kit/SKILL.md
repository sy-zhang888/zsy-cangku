# 概念学习资料生成器

把任何一个陌生的概念，变成一份"看得懂、记得住、查得到"的图文学习资料。

## 适用场景

- 用户给出一个概念名称，希望理解它是什么、怎么工作
- 需要为一个新技术术语制作自学材料或教学材料
- 需要把一组相关概念整理成结构化笔记

## 不适用场景

- 用户只要一句话定义（直接回答即可，不要生成整份资料）
- 需要可执行代码、需要真实运行的项目（这不是本 Skill 的目标）

## 输入信息

| 输入项 | 必填 | 说明 | 缺失时的默认处理 |
| --- | --- | --- | --- |
| 概念名称 | 是 | 要学习的概念，中英文均可 | 无默认值，必须向用户确认 |
| 学习者年龄/背景 | 否 | 影响类比和用词的选择 | 默认 8-12 岁，零基础 |
| 输出目录 | 否 | 资料保存位置 | 默认 `learning-materials/` |
| 输出文件名 | 否 | 单个 HTML 文件名 | 默认用概念的英文小写连字符形式，如 `agent.html` |
| 关联概念 | 否 | 需要在"这个概念不是什么"里对比的对象 | 默认自动挑选 2-3 个最常被混淆的概念 |

## 生成步骤

### 第 1 步：定锚点

先回答三个问题，再动笔：

1. 这个概念**解决什么问题**？（没有它之前人们怎么办）
2. 它的**最小可运行结构**有几块？（超过 5 块就必须合并）
3. 它**最容易被误认成什么**？

### 第 2 步：找类比

为每个概念找一个孩子生活里见过的东西做类比。要求：

- 类比物必须在 8-12 岁的日常经验范围内（厨房、学校、快递、游戏、积木）
- 一个类比只讲一个侧面，不要指望一个类比解释全部
- 明确写出"这个比喻在哪里开始不准"，防止类比误导

### 第 3 步：查来源

**在写任何结论之前先查证**。要求：

- 至少 2 个来源，其中至少 1 个是官方一手来源（厂商文档、论文、标准规范、百科条目）
- 优先顺序：官方文档 > 权威百科 > 高质量技术博客 > 二手转述
- 记录来源的标题、URL、以及它支撑了哪一个具体结论
- 查不到的数字宁可不写，也不要编造

### 第 4 步：写内容

按下面的输出结构逐段写。写作口径：

- **不笼统**：每个机制都要有"它具体做了什么动作"的说明，禁止只写"它可以智能地处理"
- **不啰嗦**：每个小节控制在 3-6 句话；能用表格的不用段落；能用图的不用表格
- **有画面**：每个概念至少配 1 张内联 SVG 示意图，图要标注关键部件
- **有边界**：每份资料必须写清楚"它做不到什么"

### 第 5 步：做自检

对照最后一节的检查清单逐条打勾，不通过就改，改完再交付。

## 输出结构

生成单个 HTML 文件，页面自上而下包含以下板块（顺序不可调换）：

```
1. 标题区        —— 概念名 + 一句话定义（不超过 30 字）
2. 学习目标      —— 3 条，用"学完你能……"开头
3. 先问三个问题  —— 3 个引导性核心问题，后文会回答
4. 它像什么      —— 生活类比 + 内联 SVG 类比图
5. 它怎么工作    —— 组成拆解 + 内联 SVG 机制图 + 逐步流程
6. 用在哪儿      —— 1 个具体的、有名字有数字的应用场景
7. 容易搞混      —— 对比表格（这个概念 vs 相近概念）+ 使用边界
8. 自测三题      —— 3 道简答题，附折叠的答案
9. 资料来源      —— 编号列表，含标题、URL、支撑了哪条结论
```

### HTML 技术要求

- 单文件，无外部依赖，直接双击可在浏览器打开
- 内联 `<svg>` 画图，不使用需要联网的图片
- 浅色主题，正文 16px 以上，行高 1.7
- 每个板块用卡片区分，配色不超过 3 种主色
- 每个 SVG 带 `<title>` 和 `<desc>`，保证可读屏

## 资料来源要求

| 要求 | 具体标准 |
| --- | --- |
| 数量 | 每份资料 ≥ 2 个来源，其中 ≥ 1 个官方一手来源 |
| 类型 | 官方文档、厂商工程博客、标准规范、百科条目优先 |
| 可核查 | 必须给出完整 URL，且 URL 在生成时已验证可访问 |
| 可追溯 | 每个来源要标注"它支撑了本文的哪一条结论" |
| 禁区 | 禁止引用无法验证的自媒体转述；禁止编造 URL；数字必须能追溯到来源 |

## 自检要求

交付前逐条检查，全部通过才算完成：

- [ ] 一句话定义不超过 30 字，且没有使用"智能""赋能""一体化"这类空词
- [ ] 类比来自 8-12 岁的日常经验，并且写明了"比喻在哪里不准"
- [ ] 机制部分写清了"具体做了什么动作"，没有停留在形容词层面
- [ ] 至少 1 张内联 SVG 图，图上标了关键部件名称
- [ ] 应用场景是具体的（有场景名、有步骤），不是"可以广泛应用在各领域"
- [ ] "容易搞混"用表格对比了至少 2 个相近概念
- [ ] 明确写出了使用边界 / 做不到的事
- [ ] 来源 ≥ 2 个，含 ≥ 1 个官方来源，URL 已验证
- [ ] 全文无敏感信息、无密钥、无个人隐私
- [ ] HTML 在浏览器中可直接打开，无外部依赖

## 示例调用

用户输入：

```
用这个 Skill 学习"向量数据库"
```

期望动作：

1. 确认概念为「向量数据库」，学习者默认 8-12 岁
2. 检索官方与百科来源
3. 按输出结构生成 `learning-materials/vector-database.html`
4. 逐条自检后交付，并说明用了哪些来源、做了哪些人工核查
