大模型的上下文

模型一次能"看见"的文字总量，问的和答的共用这一块地方。

学完你能做什么

  • 用"黑板"这个比喻解释上下文窗口，并说出它装了哪四样东西
  • 解释为什么聊久了 AI 会"忘事"，以及中间部分为什么最容易被忘
  • 在文档太长、塞不下的时候，说出两种以上的应对办法

先问三个问题

1. 为什么聊了半小时之后，AI 好像把开头说好的要求忘掉了？
2. 我把一整本书复制给它，它为什么还是读不完？
3. 上下文窗口越大就越好吗？

它像什么：一块写满了要擦的黑板

把大模型想成一个站在黑板前的学生。这块黑板大小是固定的。你们说的每一句话、它写的每一个字、你贴上去的资料，全都要写在上面。

黑板写满了还想写，就只能把最早写的内容擦掉。这就是为什么聊久了它会"忘事"——不是它变笨了，是最早那几行已经被擦掉了。

这个比喻在哪里不准：真实的黑板擦掉就是真的没了。而模型这边，被挤出去的内容只是"这次看不见了"，并没有从世界上消失；另外很多产品在窗口快满时会自动把前面的对话压缩成摘要，而不是直接丢掉。

它怎么工作

用"块"来量，不是用字

黑板的大小不按字数算，而按 token（词元）算。token 是模型读文字的最小单位，中文里一个 token 大约相当于半个到两个汉字。你输入的内容、模型输出的内容，还有它"思考"时写的内容，三样全都要占这块黑板。OpenAI 的官方文档就是这么写的：上下文窗口限制的是"单次请求里能用的 token 上限，包含输入、输出和推理 token"。

它是怎么一点点被写满的

  1. 第 1 轮：你的问题 + 它的回答，留在黑板上
  2. 第 2 轮：第 1 轮的全部内容 + 新问题 + 新回答，一起留在黑板上
  3. 第 3 轮：前面两轮全部 + 新问题 + 新回答……

也就是说，每一轮模型其实都在重新读一遍完整的黑板。所以聊得越久，每句话的代价就越贵。

大并不等于好

Claude 的官方文档专门提醒：上下文越大，并不意味着效果越好。随着 token 数量增长，模型的准确率和"能不能把信息找回来"会下降，这个现象被叫做 context rot（上下文衰退）。所以"往里塞多少"和"塞什么"同样重要。

用在哪儿：一次读完 300 页的书

老师让你一周内读完《城南旧事》并做一份读书报告。你想让 AI 帮忙，于是把整本书复制进去——结果被提示"内容过长"。

办法怎么做适合什么情况
分块读把书切成 5 段，每段先做摘要，最后把 5 份摘要合成一份报告书不算特别厚，且要整体理解
先找再读只把和问题相关的那几页摘出来交给它你只想回答几个具体问题
压缩历史聊到一半时，让它把前面的对话总结成一小段，带着这段重新开聊对话已经很长，快撑满黑板
换个长窗口换用上下文更大的模型其他办法都麻烦，且你愿意接受更贵的费用
顺手记住一个小技巧：把最重要的要求写在最前面，或最后面重复一遍，别夹在一堆资料的中间——那里最容易被忽略。

容易搞混的三件事

名字它是什么关键区别
上下文窗口这一次对话能用的临时黑板对话结束就没了，换一个对话就换一块黑板
模型的知识训练时学到的东西不用你贴给它它也会，但可能过时，且说不出出处
长期记忆 / 外部资料库存在硬盘上的东西要用的时候得先"检索"出来贴到黑板上，才起作用

使用边界（几个常见误会）

  • "窗口大 = 什么都记得住"：不对。哪怕没写满，中间部分也容易被忽略，内容越多准确率越低。
  • "它记得我上次说的话"：不对。换一个新对话，黑板就是空的，它对你一无所知。
  • "模型数字都一样"：不对。不同模型的窗口大小差别很大，从十几万到上百万 token 都有，要看具体模型的文档。
  • "超出就一定能提示我"：不一定。有时超出的部分会被直接截断，你拿到的回答看起来完整，其实漏读了尾巴。

自测三题

1. 你给 AI 一段 5000 字的资料，要求"用 3 句话总结，且必须提到第 200 页提到的那个地名"。为什么这个要求容易失败？
看答案

因为那个地名被埋在长资料的中间，而中间位置的信息最容易被模型忽略。更好的做法是把关键资料单独摘出来，或者把要求放在开头和结尾各说一遍。

2. 同一段对话，第 1 轮花了 100 个 token，第 10 轮为什么花的 token 比第 1 轮多得多？
看答案

因为每一轮模型都要重新读一遍黑板上此前所有内容，前九轮的对话全都还在上面，是累加的。

3. 上下文窗口变大会带来什么新问题？
看答案

内容变多会让模型的准确率和信息召回下降（context rot），同时每轮重读的成本也更高。所以"塞得多"不等于"做得好"。

资料来源

  1. Anthropic 官方开发者文档，《Context windows》
    https://platform.claude.com/docs/en/build-with-claude/context-windows
    支撑结论：上下文窗口是模型生成回答时所能参考的全部文本，包含回答本身，相当于"工作记忆"；内容随轮次逐步累积；token 越多准确率与召回越差，即 context rot；输入、输出、推理 token 全部计入。
  2. OpenAI 官方开发者文档，《Conversation state》
    https://developers.openai.com/docs/guides/conversation-state
    支撑结论：上下文窗口是单次请求可用的最大 token 数，包含输入 token、输出 token 与推理 token；超出上限的内容可能被截断。
  3. 百度百科，《上下文窗口》
    https://baike.baidu.com/item/上下文窗口/67367067
    支撑结论：中文定义；与"上下文长度"是理论上限、窗口是实际使用量的区别；窗口大小受训练序列长度、注意力计算成本与显存制约。
