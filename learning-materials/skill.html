Skill（技能）

装在文件夹里的一本岗位手册，让通用 AI 临时变成某件事的熟手。

学完你能做什么

  • 说清 Skill 和普通提示词（Prompt）的本质区别
  • 画出一个 Skill 文件夹里的东西，并解释"三级加载"是怎么回事
  • 把一个你反复做的任务，写成一份能被复用的 Skill 说明

先问三个问题

1. 我每次都要跟 AI 重复一遍"记得用表格、记得标出处"，有没有办法只说一次？
2. Skill 就是一个保存起来的提示词吗？
3. 装了很多 Skill 之后，黑板（上下文）会不会被塞满？

它像什么：书架上的岗位手册

想象公司来了一位什么都会一点、但什么都不精的新同事。你没法每次都从头教他怎么做报销、怎么做会议纪要。于是你给他在书架上放了几本岗位手册。

平时他只扫一眼书脊上的书名（几乎不花力气）。只有当你真的说"帮我报销这笔差旅费"时，他才走过去把那本手册抽下来翻开；手册里写着"第 7 页有表格模板"，他才会再去翻第 7 页。

Skill 就是这套机制：手册平时不全摊开，用到了才打开。

这个比喻在哪里不准：人会真正"学会"手册里的内容，下次不用看也记得。AI 不会——每次对话它都要重新翻开读一遍，并没有真的把知识装进脑子里。Skill 省的是你重复交代的功夫，不是模型的记忆。

它怎么工作

一个 Skill 就是一个文件夹

最小只要一个文件 SKILL.md。讲究一点的话，里面还能放脚本、参考资料和模板：

my-skill/
├── SKILL.md          # 必须有：说明这个技能怎么用
├── scripts/          # 可选：可以被直接运行的脚本
├── references/       # 可选：用到才读的详细资料
└── assets/           # 可选：模板、配置等固定素材

文件开头的那几行很重要

SKILL.md 的最上面必须有一小段 YAML 元数据，其中 name 和 description 是必填的。名字只能用小写字母、数字和连字符，还要和文件夹同名；描述要写清"这个技能干什么、什么时候该用它"。

---
name: my-skill
description: 干什么活，以及什么时候该用它
---

（下面是正文：步骤、注意事项、检查清单）

三级加载：省黑板的关键

最妙的在第三级：模型运行一个脚本时，读进黑板的是运行结果，而不是脚本本身的代码。所以让模型"跑一段排序程序"，比让它"一个个数着排序"便宜得多，也更不容易出错。

用在哪儿：给 PDF 填表的技能

AI 其实挺懂 PDF 的，但直接动手改（比如填写一张申请表）就不太行。Anthropic 举的例子是：他们为此做了一个 PDF 技能。

  1. 开头写明"处理 PDF 文件、提取表格、合并文档时使用"
  2. 正文给出提取文字的标准做法，以及该用哪个工具库
  3. 正文只留主干，把"怎么填表单"的细节单独放进 forms.md
  4. 附带一个现成脚本，用来读出 PDF 里有哪些待填的空

结果是：用户只是说"帮我填这份表"，模型就知道该翻哪本手册、该跑哪个脚本；而填表细则和脚本代码平时一点黑板都不占。

容易搞混的四件事

名字是什么关键区别
Skill文件夹里的一整套说明 + 资源长期复用、按需加载、可以带脚本
提示词 Prompt这一次对话里说的话一次性，下次要重新说
工具 Tool真正产生动作的"手"工具负责做，Skill 负责告诉它什么时候做、按什么顺序做
上下文 Context黑板本身Skill 是往黑板上放的内容，不是黑板

使用边界（几件容易踩的坑）

  • 描述写不好，技能就永远不会被用上：模型是靠 description 判断该不该翻这本手册的，写得太泛就永远触发不了。
  • 正文写太长会浪费黑板：一旦触发，整篇都会读进来。细则应该拆到单独文件里。
  • 它不是"学会"，是"查阅"：模型每次仍要重新读一遍，并不会记住。
  • 不是所有 AI 产品都支持：Skill 已经是一个开放的规范，但各家支持程度不同，附带的脚本能否运行也取决于具体环境。

自测三题

1. 有人说"Skill 就是保存起来的提示词"。这个说法差在哪？
看答案

提示词每次都要重新说、且一次性全部进黑板。Skill 是文件夹：平时只占约 100 个 token 的招牌，触发后才读正文，脚本和细则还能再往后拖；而且它可以附带能真正运行的脚本。

2. 你装了 30 个 Skill，为什么黑板没有被塞爆？
看答案

因为平时只加载每个 Skill 的名字和描述（约 100 个 token），正文和附带文件都是用到了才读进来。

3. 你的 Skill 一直没被自动用上，最可能是什么原因？
看答案

最常见的是 description 写得太笼统，模型看不出它和当前任务的关系。描述里应该写清"干什么活"和"什么情况下该用"，并带上容易被匹配到的关键词。
